## 2026-11-24

- Added an AI-assisted product import (Excel/CSV) to the admin, with column mapping review, category, brand, and discount review, preview, and queued import into the catalog (LFP-954). New package `packages/product-import` (`Lunar\ProductImport`), turned on with `PRODUCT_IMPORT_ENABLED` and the `catalog:import-products` staff permission; the host registers `ProductImportPlugin`. Staff upload one or more XLSX, XLS, or CSV files from **Import** on the product list; every sheet is staged in the package's own tables, and one AI request per sheet suggests the column mapping from the headers, column statistics, and up to 30 samples per column (`product-import.ai.sample_size`; provider, model, and optional own key from `PRODUCT_IMPORT_AI_*`). Nothing reaches the catalog until staff approve the preview. Mappings can be saved as profiles and are offered for files with matching headers. `product-import:prune` removes staged rows and files after the retention period. New dependencies: `maatwebsite/excel` ^4.0 and `laravel/ai` ^1.4 (now a direct requirement).
- Product import reads shop exports through conventions the AI describes per column, without any platform list or choice (LFP-954): number and date formats; list, category path, and packed-item separators (`none` for one item or one level), so two sheets of one import can separate their categories differently; weight and length units per sheet, chosen from the store's unit codes; a row type column whose types get meanings (product with one variant, product with variant rows, variant, not imported, not shippable); parent references by ID, `id:N`, or SKU across files, including separate variants files; option pairs that variant rows number differently; packed list items whose `:`-separated parts are named, skipped, or kept; coded status, stock, backorder, and shippable values; and image URLs with a size suffix. Staff correct these per column in the mapping step, and profiles keep them. Every cell is cleaned first (formula escape apostrophes, literal `\n` in descriptions, HTML entities in names).
- Product import writes brands, categories, options, and option values first, after staff review them together with option names and properties from cells, then products, variants, and prices in one transaction per product group (LFP-954). Existing variants are matched by SKU or EAN, so importing a file again does not create duplicates. The import also writes tags, GTIN, MPN, dimensions, and purchasability; meta title, description, and keywords columns map to the product type's attributes, labelled with their attribute group ("Search Engine Optimization › Title"), and a URL slug column (`product.slug`) gives new products their URL in that language, with a number suffix when another product uses it; existing products keep their URLs. Up-sells and cross-sells are added, then images are downloaded from public HTTP and HTTPS addresses only (`product-import.images.*`). The import writes the row's price and never writes or clears a compare price; a sale price is not imported, and the preview warns with the sale price and its dates so staff can correct the price.
- Product import: discounts in a file become Lunar discounts (LFP-954). A discount amount or percent with its start and end is collected per kind, value, and dates and reviewed like categories: it uses an existing automatic discount limited to products or variants with the same value and dates, or creates one without a coupon for every channel and customer group, and staff can pick another discount, edit the one to create, or skip it. The variants that carry it are added to that discount, so the shop shows the discounted price only between its dates; a date without a time lasts the whole day. The preview warns about a discount that already ended or a fixed amount the shop would not apply.
- Product import failures can be fixed from the result page (LFP-954). Failed rows can be downloaded as CSV, corrected, and retried; the row correction form shows prices, numbers, dates, codes, and lists the way their column reads them. Images that failed to download are listed with their reason, staff can correct their URLs, and **Retry failed images** downloads them again without writing any product.
- Product import fixes from the end-to-end run on `webshop-demo` (LFP-954). Imported products, categories, and discount links are created as the store's own model classes from Lunar's model manifest, so a host app that replaces `Product` or `Collection` (as `lunar-frontend` does) gets its class in the model events and its listeners no longer fail the product groups; search syncing stays off for those classes while writing. The mapping step separates its columns with a visible divider and more spacing, in the light and the dark theme. In the preview, staff can **Include** a row that its type skips (for example a "grouped" row) as a product with one variant, a product whose variants are other rows, or a variant; the choice is kept when the import is staged again (new `role_override` column on `lunar_product_import_rows`), and a new category, brand, or option value of the row that needs a decision sends the import back to the value review. Rows skipped as existing variants or for a skipped option value name the setting that decides them. Each downloaded image keeps its own file, named after the product with a number suffix like an admin upload; before, two image URLs ending in the same file name (`…/1000.jpg`) shared one file in the product's folder. The new import option **Link images to variants** (off by default) links the product images of a variant row to its variant, adding an image the product does not have yet, so the shop shows them when that variant is chosen; the product row's images, and those of a product with one variant, stay on the product only.
